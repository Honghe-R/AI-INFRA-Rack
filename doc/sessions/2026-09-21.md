# 2026-09-21 — The demo goes live, and the assistant's loop becomes watchable

A work record, not a specification. Three threads: the app is deployed and reachable at
`https://202.120.39.134:5500` on a machine that has no Docker, no usable system PostgreSQL, and
exactly one open port; the assistant stops doing its tool calls in silence and starts showing
the loop while it runs; and the demo surfaces gain what a visitor needs — a watermark, an
About, an avatar, a model menu.

## What landed

### The deployment: one port, no Docker, a PostgreSQL nobody could install with `apt`

The constraints are the design. `front` is Ubuntu 20.04 with Apache holding 80 and 443 for four
other SJTU vhosts, a system PostgreSQL 12 that cannot be used, and a firewall that leaves
**5500** as the only reachable port — verified by probing 5501, 8443, 9000, 9443, 55432, and
59000, all of which are blocked. So the demo is a self-contained stack on one port, and every
component had to be installed without root package management:

| Piece | What runs | Where |
| --- | --- | --- |
| Database | PostgreSQL 16.10 + PostGIS 3.5.0 from conda-forge | `/var/lib/ai-infra`, port 5432 on loopback |
| Object store | MinIO, rootless | port 9000 on loopback |
| API | `apps/api`, Node v22.19.0 via nvm | port 8787 on loopback |
| Edge | `scripts/serve-demo.mjs` | port 5500, the only public one |

All four are **system** systemd units (`ai-infra-postgres`, `ai-infra-minio`, `ai-infra-api`,
`ai-infra-edge`) running as `sunwq`, with absolute Node paths because systemd does not read
`.bashrc` and therefore does not know about nvm.

### `scripts/serve-demo.mjs` — the edge, and its three invariants

One file serves the built SPA and proxies `/api`, minting HS256 dev tokens so the demo needs no
login. It also exposes `/__dev/identities` (the eight seeded identities) and proxies
`/<bucket>/*` to MinIO. Three properties are load-bearing, and each one was a defect first:

1. **`Host` is preserved** on the bucket route. MinIO signs SigV4 over the host, so rewriting it
   to the loopback origin breaks the signature.
2. **The client's own `Authorization` is forwarded, and no token is ever added.** Object I/O is
   header-signed by the client; the edge deleting that header produced `403`s on every upload.
3. **`x-dev-subject` never reaches the API.** The API authenticates on the bearer token, so the
   header that chooses which token to mint is the edge's business alone.

### The certificate took three attempts, two of them instructive

A certificate for an IP address has to be self-signed, and both obvious ways to make one fail:

* `-addext basicConstraints=CA:FALSE` plus Ubuntu's default OpenSSL config produced a
  certificate with **two** `basicConstraints` extensions — `UNABLE_TO_VERIFY_LEAF_SIGNATURE`
  and `CERT_AUTHORITY_INVALID`.
* Correcting that with a leaf whose subject was `CN = AI Infra Demo Root CA` — the *same* as its
  issuer — produced `DEPTH_ZERO_SELF_SIGNED_CERT`. A leaf must have a subject **different** from
  its CA, or a verifier cannot tell the chain from a self-signed loop.

The working recipe is a dedicated `demo-openssl.cnf` with `-subj` given per command, and a leaf
carrying `subjectAltName = IP:202.120.39.134, DNS:ai-infra.sjtu.edu.cn` so the same certificate
survives the domain hand-off.

### The assistant stops working in silence

The complaint was precise: the chatbox called tools without saying so, and a turn that spent
most of a minute in the model looked exactly like a turn that had hung. Three steps, each
independent of the next:

1. **Disclose the calls.** `finalize` awaited its turn append, so the ledger row exists before
   the reply does; usage rows now carry the model they were spent on; the transcript renders the
   tool calls a turn made instead of leaving them in a server log.
2. **Show the rounds.** `trace` gained `rounds` (with `toolCalls` derived from them via
   `flattenToolCalls`), and each turn renders a disclosure: how many rounds, how many tools, and
   per round its model time, its tokens, and each call with its own duration and outcome.
3. **Stream them.** `POST /api/v1/assistant/chat?stream=1` writes newline-delimited JSON as the
   loop runs and ends with the *same* envelope the plain call returns — same body, same
   authorization, same envelope, same errors, so the two modes cannot drift. The orchestrator
   gained an `onEvent` hook emitting `round_started` and `round`; a hook that throws is swallowed,
   because a reporter must never be able to fail the thing it reports on. Once the headers are
   out a status cannot be revised, so a mid-stream failure is written as a `{type:"error"}`
   record — which is the point: **a turn that times out keeps the rounds that completed** instead
   of losing them with the error.

In the UI, rounds land on the assistant's placeholder as they arrive and a *running* turn holds
its disclosure open, so the loop is watched rather than discovered afterwards. A finished turn is
left however the reader left it, so closing it mid-turn is not undone by the next round and the
answer does not snap shut when it lands. The envelope replaces the placeholder wholesale, so the
streamed rounds are not counted twice.

### The demo surfaces

* **Watermark.** `AI Infra Planner Demo` on the sidebar, the main view, the canvas surface, the
  authoring panel, the canvas aside, the inspector, the projects view, the assistant frame, and
  the bottom drawer while expanded. It is a **CSS mask** tiled with `mask-repeat: repeat` at
  `250px 130px`, so it repeats without limit in both directions and has **no child elements** —
  which is why the check asserts on `mask-image` and not on DOM nodes. Colour comes from
  `background-color: var(--text)` so it follows the colour scheme.
* **About.** A dialog in Settings naming the app's function and its creator, Professor Weiqiang
  Sun, with both links; Escape and a backdrop click dismiss it, a click inside does not.
* **Avatars.** The account control shows the user's initials on `--accent`.
* **The composer** gained a model menu (populated from the server, not the bundle), a resize
  handle at 320–1100px, Escape to collapse scoped to the frame, and working file uploads.

## Decisions worth keeping

* **The turn stays request/response; streaming is opt-in and additive.** `?stream=1` changes
  only whether the rounds are written as they complete or returned with the envelope. A second
  contract would have been a second thing to keep in step, and the failure modes of the two
  modes would have diverged exactly where it matters. A reader that ignores the stream still ends
  up with the whole turn, because the envelope is last.

* **A watermark is a build-time value.** An operator-switchable watermark is not a watermark, so
  `VITE_DEMO_WATERMARK` is baked in at build and an empty value renders nothing, which is how a
  production build turns it off.

* **The provider is the endpoint's host, not the protocol it speaks.** The composer's chip reads
  `models.sjtu.edu.cn`; "openai-compatible · deepseek-chat" tells a reader nothing about whose
  model is answering. The protocol is worth a tooltip, not a label.

* **Pace the probes against the gateway's own rate limit.** Only one API key is in play, and
  probing several models quickly returns `429` for every model after the first. `test-models.mjs`
  therefore probes each model at **two levels** — the gateway directly, and through
  `/assistant/chat` — with a delay between models and a retry that honours the interval the
  gateway names.

* **A verification that cannot fail is not a verification.** `--insecure` on the `ui-shot`
  harness is opt-in for exactly this reason: the harness is worth having because it shows what a
  real browser shows, and quietly ignoring certificates everywhere would hide the one thing a
  reader of the deployment most needs to see.

## Defects

**Two I introduced, both caught, both worth recording.**

* **A blank page passed 488 tests.** Refactoring the composer, I dropped a
  `const sessionRef = useRef(null);` line. Every unit test still passed, because the web tests
  render **static markup** — a missing hook reference is invisible to them. The deployed page was
  simply blank. It was found by capturing the browser console over CDP, which is why the runbook
  now carries a check for exactly this and why the check exists at all.
* **The model probe was wrong, and I believed it.** `test-models.mjs` first sent only
  `projectId`; the assistant needs `scenarioId` and `revisionId` too, and answered
  `VALIDATION_FAILED — revision_id: required`. I read that as **`qwen` being broken** and `claw`
  returning raw JSON. Both were artifacts of my own probe. Corrected in the runbook with the
  measured table: `deepseek-chat` 1.2s/2.4s, `deepseek-reasoner` 1.2s/4.3s, `qwen` 0.6s/47.4s,
  `qwen3.8-27b` 1.4s/13.9s, `claw` 1.7s/3.8s, and `minimax` / `minimax-m2.7` answering without
  the JSON envelope.

**Three the environment produced.**

* **`SignatureDoesNotMatch` on every object call.** `minio.env` had been regenerated at 13:26
  while `app/.env` still held the 12:20 credentials. Realigned, with a guard and a repair recipe
  in the runbook.
* **MinIO's download is gone.** `dl.min.io` answers `410` — the project archived that path. The
  GitHub release asset (`RELEASE.2025-09-07T16-13-09Z`) works, but its published filename differs
  from the documented one, so `sha256sum -c` **fails against a correct binary**; the hashes have
  to be compared by hand.
* **The seed read the wrong field name.** `dev-seed.mjs` read `organisation.organisationId` from a
  repository call that returns the American `organizationId`, so `assignRole` received
  `scopeId: undefined` and the seed died on
  `null value in column "organization_id"`. Fixed — and it only reproduces against a database
  where the owner has no membership yet, which is why a fresh database was the only way to see it.

**One operational, and it cost me time.** `~/.ssh/config` puts host `front` on **port 3122**.
Dialing `202.120.39.134:22` directly connects at the TCP level and then resets during the key
exchange, which reads exactly like a dead host or a ban. The deployment was up the whole time;
the egress IP on this machine is now `141.11.146.62`, which is worth knowing if port 22 is ever
whitelisted by source.

## Verification

* `npm test` fully green: **492** web tests and **750** across the other workspaces. Five are new
  today — four web, one API — and they pin the seams that had no coverage at all: the store
  growing the placeholder as rounds stream in (and *not* double-counting them when the envelope
  replaces it), the transcript rendering a running turn's disclosure open and a finished one's
  closed, a turn stored before rounds existed still disclosing its tools, and the streamed API
  route reporting every round before the envelope.
* **Streamed turn, measured through the public edge** (not the loopback API): round 1 at
  **3.09s**, round 2 at **9.21s**, envelope at **9.49s** — round 1 was visible 5.8s before the
  turn ended, so nothing is buffering, and the rounds on the wire are exactly `trace.rounds` in
  the final envelope.
* **Driven in a real browser against the deployment:** the live turn's `.turn__rounds` was
  `open: true` while `.turn__thinking` was present, stayed open when the turn ended, and a turn
  restored from history was collapsed — with **zero console errors**.
* The deployed bundle is the built code: `index-DIHoXBRN.js` carries the streaming client, and a
  dry-run rsync of all three source trees reports no drift from the pushed commit.
* The runbook (`doc/architecture/demo-deployment.md`) grew from 25 to **29** checks, including the
  streaming contract, the live-disclosure behaviour, and the blank-page check, plus a §7.1 on
  driving the deployed UI.

## Open

* **The provider is slow, and the loop now proves it.** A single round measured 53.5s and one
  turn spent 55.8s in the model against a 60s `LLM_TIMEOUT_MS` — a turn can be killed by the
  timeout with nearly all of its budget in one call. The tool calls themselves cost **19ms**. The
  next useful change is not more visibility but a longer timeout, or a per-call budget that fails
  a slow round without discarding the turn.
* **`minimax` and `minimax-m2.7` answer outside the JSON envelope.** `minimax` also writes
  ` thinking…` into `content`. Both need envelope parsing for reasoning models before those ids are
  worth offering.
* **`LLM_MODELS` still carries aliases.** `deepseek-chat,deepseek-reasoner,minimax,minimax-m2.7,qwen,qwen3.8-27b,claw`
  includes duplicate aliases and an undocumented `claw`; trimming it to the four real models is
  documented and not yet applied.
* **The certificate renewal timer is not installed.** §8.3 of the runbook has the certbot timer
  for both servers and it has not been added.
* **Docker was never purged.** §11.1 records the unevaluated Docker install on the same host.
* **Smaller, known:** the About dialog has no focus trap; the sidebar watermark scrolls away at
  short viewports; a pre-existing React "unique key prop" warning appears on the projects page
  and is not from today's work; and `STORAGE_PUBLIC_ENDPOINT` (§9.1) is still a refinement worth
  considering.
