Two facts worth keeping. A change set commits or fails as one, and that atomicity is the
command's **own** savepoint rather than the caller's transaction — otherwise a caller that
caught the error and continued would commit half a set. And a run that no longer emits a
diagnostic now marks the live one `RESOLVED`: previously only a re-issue superseded it, so a
finding whose condition had been fixed stayed open forever.

### The import path, first half

`ad6077c` binds a project asset version to a revision — `list_asset_bindings`,
`create_asset_binding`, two routes, and the `Import & Map` surface.

The decisions that took the most thought:

* **A binding does not advance the draft ETag.** `import-adapters.md` says *applying* an
  import is the typed change set that advances it; pinning a source is provenance. That makes
  this the one write in the surface with no `If-Match`, so it is recorded as an explicit
  exception in `backend-api-contracts.md` rather than left as an omission. Concurrent binds
  of one version and role serialise on the revision row.
* **An interface's failure domain and phase come from its source.** An interface declaring its
  own is `redefines_source`, an ERROR — so the form inherits them and says so instead of
  offering a choice the store would refuse. This is also what made the tool buildable at all:
  there is still no failure-domain route.
* **`list_asset_bindings` is not a generic list.** A binding stores a version id; which asset
  that version belongs to lives in another bounded context, so the tool resolves the identity
  in one bounded query. A version that no longer resolves is `null`, never a guess.

`9382fdc` added the interface placement tool, which is the entity whose absence the catalog
reports as `connectivity_missing` and the one that makes a supply firm.

### Text and colour

`0e476b0` darkened the light scheme's greys. This was filed as taste and turned out to be a
defect: `--text-subtle` was 3.10:1 on white and 2.71:1 on the tinted fills while carrying
small captions, against a 4.5:1 floor. The values are solved rather than picked — each keeps
its hue and drops its mean until the target is met on the **worst** surface it can land on —
giving a ladder of 18.2 : 9.3 : 5.7, a geometric step of ~1.7× between each so the two greys
darken without collapsing into one another.

## Defects

Split deliberately, because the two halves have different lessons.

### Reported by the user

* **The chat printed its own envelope** (`d9c0ba8`). The prompt asks for
  `{"type":"message","payload":"…"}`, the provider writes literal newlines inside the payload,
  the JSON parse fails, and the old code fell back to the raw text — so the *degradation was
  the bug*. Recovery is now deterministic: escape control characters inside string literals
  only, tracking backslash escapes.
* **The plan-only fallback was a one-way latch** (`aa64f03`). The failure count only ever
  incremented, and because the degraded canvas renders no tiles, no tile could load to clear
  it. Switching to a provider that answered changed nothing. The comment said "a *run* of
  failures", which is consecutive-failure semantics; the implementation was cumulative.
* **Selection was outlined in the layer's own colour** (`5ed1538`), so the border answering
  "which one is selected" was the border the object already had.
* **A render loop on commit** (`d9c0ba8`). Three separate sources of new state per render:
  `setDirty` rebuilt the workspace object when nothing had changed, `bindChangeSet` did the
  same, and `onDirtyChange` was an inline arrow handing the child a new prop every render.
* **The info bar moved the map** (`d9c0ba8`). The draw controls were a `banner` slot, which
  inserts a row above the map and so changes the projection under a drawing user's cursor.
* **`/api/v1/me/permissions` in an infinite loop** (`0e1b091`), ~190/second.
* **The asset upload surface was unreachable** (`10bad1c`). `Can permission="asset.write"`
  passed no `projectId`; `asset.write` is project-scoped and the server answers an unscoped
  question about it with a determined refusal. The button rendered a fallback forever.

### Introduced by me, and caught by the user

This list is the point of this section.

* **The overlays on the map were unclickable** (`37abdc8`). The map pans by capturing the
  pointer, and `setPointerCapture` retargets the rest of the gesture — so a press on an
  overlay resolved the `click` onto the surface and the control's handler never ran. Moving
  the controls *onto* the map is what armed it; in the row above, the surface never saw them.
* **The permission loop** (`0e1b091`). `withDevIdentity()` used as a default parameter, which
  is evaluated every render, became a new effect dependency every render.
* **A doc comment that drifted onto the wrong function**, from an earlier insertion landing
  inside it.

Three times, a defect I had introduced was reported by hand after a green automated check. The
common shape: **the check exercised the code without exercising the browser.** `element.click()`
dispatches straight to the element and skips hit testing, pointer capture, and every listener
on the way, so it passed on a control a user could not click. And the probes ran after every
click, so "before" and "after" were the same reading.

## Verification

Two gaps closed, both in `scripts/ui-shot.mjs`, both because a green suite was not evidence:

* **`--real-click` and `--real-drag`** drive the browser's input pipeline over CDP. Pointer
  capture and gesture thresholds only behave for genuine input; anything else is not being
  tested. This is now the required way to claim a control works.
* **The canvas exposes `data-zoom` and `data-centre`.** A frozen map and a map nobody clicked
  look identical from outside. This started as temporary instrumentation to find the latch and
  is worth keeping as a test hook.

Where a browser is not available, the stylesheet is measured rather than assumed — the same
technique `shell-layout.test.js` already used: `text-contrast.test.js` recomputes every
contrast ratio against every surface, `canvas-selection.test.js` asserts the selection token
is disjoint from the layer hues, and the toolbar test asserts the labels drop at the measured
threshold rather than an estimated one.

A third habit, adopted after being wrong twice: when a test is written to pin a fix, run it
against the **pre-fix** code and watch it fail. Several in the suite were confirmed that way.

## Decisions worth remembering

* **Refuse what the store cannot hold; accept domain violations so the validator reports
  them.** A quarantined asset version cannot be bound; a duplicate is a `409`. A design
  mistake is left to be a diagnostic.
* **One list, one place.** `scripts/lib/dev-identities.mjs` is read by the seed, the dev
  server, and the menu, because a list written three times drifts and the failure is a menu
  entry that authenticates as a user nobody created.
* **The permission predicate stays dependency-free.** An import-boundary test enforces it, so
  the identity-aware fetch is injected at the app layer rather than imported into it.
* **A shared read costs a little to keep correct.** The evaluator resolves project, then
  organisation, then global, then onboarding. A role held only at project scope cannot find
  its own project — which is why each dev identity also carries a read-only organisation role.

## Open

   possible in a real session. It needs a decision rather than a patch: creating a project
   cannot be scoped to a project, so either the key's declared scope is wrong or the button
   should be gated on an organisation-scoped key.
2. **Dark mode's `--text-subtle` is 3.96:1**, below AA — the same defect as the light one,
   left alone because that request was scoped to light mode. The test records the number
   rather than asserting the failure.
3. **The import's second half** — transform, mapping, preview-merge, apply. Still
   `PENDING_ACTIONS`; nothing an import finds reaches the design graph yet.
4. **The 480px layout.** The fixed 320px aside leaves the map ~115px wide, where the overlays
   are capped to that width and overlap each other. The aside's placement, not the overlays'.
5. **The context bar's disclosure thresholds** were measured with four controls that have
   since left it, so each tier fires earlier than it needs to. Re-measure them together rather
   than one at a time.
6. **`transform_geometry`** remains the one unbuilt change kind, blocked on `spatial_transforms`
   requiring a binding.
7. **The assistant projection (T8)** — the host still declares no capabilities, so the
   assistant answers from what context it is given rather than from tool results.
