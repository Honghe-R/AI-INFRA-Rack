## Scope Decisions

Two owner decisions define this plan.

1. **Workspace first, tool second.** The workspace shell, RBAC, Project Assets, the import framework, the basemap tile proxy, and the assistant host are built before the tool. The Site and Facility Editor becomes the first tenant of a platform rather than a standalone application.
2. **All eight capabilities are validated in the first release.** `GEOMETRY`, `POWER`, `COOLING`, `WATER`, `FUEL`, `NETWORK_ENTRY`, `ENVIRONMENT`, and `PHASING` all reach validation coverage in R1. There is no capability subset to use as a scope lever.

Consequence: R1 is a platform program with the tool as its first consumer, not a tool project. It is roughly twice the size of a tool-only plan. Scope is not cut; delivery is staged (see [Sequencing and Staging](#sequencing-and-staging)).

## Definition of Done

A user can create a project and scenario, author a facility graph with canonical geometry, bind an imported CAD/KML asset through the project asset layer, run validation that emits catalog diagnostics for every capability, reach `VALIDATED`, and **publish an immutable `PUBLISHED` envelope that a downstream tool fetches by identifier with an ETag and content checksum** — with RBAC, row-level security, audit, and D21 retention enforced.

This is the narrowest path that exercises every architectural commitment in the bundle.

## Guiding Principles

1. **The specification bundle is authoritative.** A code defect and a documentation defect are fixed in the same change.
2. **Contract first.** The `infrastructure.planner.facility.v1` protobuf does not exist yet and sits on the critical path, because the API, workers, and UI all compile against it. See the [Interchange Contract](tools/site-and-facility/interchange-contract.md).
3. **Walking skeleton before breadth.** One entity, one geometry role, one real PostgreSQL, one end-to-end test — before forty-eight endpoints.
4. **Every increment ends in a test traceable to a document.** Contract tests for decisions, catalog fixtures for constraints, acceptance tests for non-functional rules.
5. **Reuse the verified store.** The initial migration is written, executed against PostgreSQL 16 with PostGIS, and behaviorally verified (cross-project reference rejection, partition pruning, row-level security). It is the one completed artifact.

**Tool surface status.** The domain capability layer specified in [Tool Surface](tools/site-and-facility/tool-surface.md) is built in `packages/facility/src/tools/`, and the validation engine's snapshot loader now reads the revision stores through the same module (`packages/facility/src/stores.js`), so there is one statement per store rather than one per consumer. All **30 read tools** and **14 action tools** are implemented, which closes every evidence bucket the catalog declares: no constraint is left nameable-but-unexplainable. The action set grew with T3 (`create_spatial_transform`, `review_spatial_transform`, `create_import_mapping`, `update_import_mapping`, `review_import_mapping`, `preview_import_merge`, `apply_asset_binding`), T5 (`publish_revision`, `request_approval`), and T6 (`request_capacity_allocation`, `decide_allocation`), on top of `run_validation`, `grant_waiver`, `revoke_waiver`, `create_asset_binding`, and `apply_change_set`. Every facility route — verification and authoring, import, capacity, governance, and lifecycle — is a thin adapter over the surface.

One operation remains in `PENDING_ACTIONS`: `pin_policy_reference` has no store, because the schema pins policy references on the rows that use them (`resilience_requirements.policy_id`, `waivers.policy_id`) and there is no revision-level pin table for it to write. Nothing else is stubbed, because a tool with no domain command behind it would have to invent a mutation path. The assistant projection (T8) is now built and wired — see its milestone row below.

**Authoring status.** The design graph is no longer read-only: `apply_change_set` commits a typed change set atomically against the draft ETag, in dependency order, and answers with both halves of its consequence — the findings it produced and the findings it cleared. Twenty-one change kinds are built: the specification's eighteen applicable ones, `set_phase` and `set_phase_capability` (without which a phase could be assigned to but never created), and T3's `transform_geometry`, which re-projects a geometry through a reviewed spatial transform and records the transform, binding, and asset version that produced it. `PENDING_CHANGE_KINDS` is empty.

Building it exposed and fixed a verification bug that defeated authoring outright: a finding whose condition no longer held was never closed, because supersession only fires when a later run re-issues the same finding — so an edit that fixed a problem left the old diagnostic `OPEN` and its capability capped, and the revision could never reach `VALIDATED`. A run now marks a live diagnostic `RESOLVED` when a constraint that ran did not re-emit it ([Verification Requirements](tools/site-and-facility/verification-requirements.md)). Verified live on the seeded campus: setting its contractual utility source to `FIRM` resolved the finding that gated POWER, COOLING and NETWORK_ENTRY; restoring it emitted a new `OPEN` finding while the resolved record stayed as history. The editing UI is built: an inspector that stages edits, a panel that commits them, footprint drawing on the canvas, and the conflict decision on a stale token. The shell's dirty-state machinery — which had no callers before this — now reports uncommitted work, so closing the tab or switching context asks before discarding a change set. Verified in the browser on the live dev stack: select, stage, commit, and the panel reports what the edit produced. See [Authoring Plan](authoring-plan.md), which refines T1 and T2 below.

### Prerequisite: Resolve the Imported Blueprints

The RBAC, map adapter, and chatbox documents are ports from an earlier project. ## Sequencing and Staging

Scope is fixed; delivery is staged so that something usable exists early.

| --- | --- | --- |
| 1 | W0–W3 | A working shell: sign-in, projects, assets, RBAC, upload and store files. |
| 2 | W4–W6 | Import pipeline, basemap, and assistant host. |
| 3 | T0–T5 | The facility tool end to end: author, validate, publish. |
| 4 | T6–T9 | Full capability coverage, work surfaces, assistant tools, operations. |

## Testing Strategy

| Layer | Test | Pins |
| --- | --- | --- |
| Contract | Protobuf round-trip and enum exhaustiveness | Interchange Contract |
| Store | ETag conditional update; an edit creates no child revision; row-level security; cross-project reference rejection; partition pruning | D1, D2, D15, D22 |
| Catalog | One positive and one negative fixture per `constraint_id` | Constraint Catalog |
| Capacity | `available_capacity` formula; contention order including explicit tie rejection | D5, D6 |
| Lifecycle | `VALIDATED` impossible with an open `ERROR`; `PUBLISHED` is one-way | D11, D17 |
| Non-functional | Acceptance-criteria suite plus a load test at revision scale limits | Non-Functional Requirements |
| Workspace | Asset immutability and deduplication; adapter conformance per format version; RBAC deny-by-default and `can()` parity | Project Assets, Import Framework, RBAC |

The catalog fixtures are the single best proxy for whether the tool works: roughly 148 tests derived directly from the catalog table.

## Risks

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Total scope of a platform plus a fully covered tool | Multi-quarter program | Stage delivery (above) without cutting scope |
| Imported blueprints carry another project's open questions | Wrong assumptions baked into the platform | Resolve them at W0 and record the answers as decisions |
| The asset and import chain (W3, W4, T3) is the long pole | Delays everything downstream | Build W3 and W4 before the tool; stub bindings only for local development |
| 74 catalog constraints with fixtures | Largest work item; easily underestimated | Generate fixtures from the catalog; one developer per capability |
| Geometry and CRS correctness, including building-local transforms and compound vertical CRS | Silent wrong answers | Golden-file fixtures with known coordinates; assert round-trips within D9 tolerances |
| Basemap provider licensing and quotas | Blocks the production canvas | The plan-only grid is the specified fallback (D16) |
| Unapproved NFR numbers | The scale test cannot pass an unfrozen budget | Freeze the remaining proposals before T9 |
| 48 endpoints and a 33-tool surface with 19 change kinds invite scope creep | R1 never completes | R1 subset fixed here; additions are a change to this document |

## Deferred Beyond R1

* IFC 2X3, IFC 4, and IFC 4X3 import. The W4 adapter framework is built in R1; KML/KMZ and DXF ship first, IFC follows in R1.1.
* Export and report generation beyond the published envelope protobuf.
* The assistant tool surface (T8) is **built**, so it is no longer deferred. What remains deferred within it: a `context_token` mint/redeem route, canvas layers for `PHASES`, `DIAGNOSTICS`, and `IMPORT_SOURCE` (so `set_layer_visibility` for those kinds and `reveal_asset_layer` validate and then no-op with a stated delta), attachment upload and the two attachment read tools, and the frozen envelope's protobuf encoding (the object is canonical JSON gzip until the T0 protobuf contract ships).
